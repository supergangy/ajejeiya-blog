[PDF OCR 프로그램](/blog/pdf-ocr-program/)을 만들고 나서 처음에는 **네이버 블로그**에 소개 글을 올렸습니다. 가장 익숙하고, 바로 시작할 수 있었으니까요.

그런데 블로그를 계속 운영하려고 생각하니 원하는 게 두 가지 생겼습니다.

1. **애드센스**로 작게라도 수익을 내 보고 싶다.
2. 글 작성과 수정을 **AI 도구로 직접** 할 수 있으면 좋겠다. 원고를 파일로 만들고, 고친 내용을 바로 반영하는 식으로요.

이 두 조건을 놓고 네이버 블로그, 티스토리, 직접 만든 블로그를 다시 비교했습니다. 이 글은 그 고민 과정과 최종적으로 고른 기준을 정리한 기록입니다. 플랫폼 정책은 자주 바뀌기 때문에, 아래 내용은 **2026년 10월 기준**이라는 점을 먼저 밝혀 둡니다.

## 먼저 결론: 한눈에 보는 비교표

| 비교 항목 | 네이버 블로그 | 티스토리 | 직접 만든 블로그 (Astro + GitHub Pages) |
|---|---|---|---|
| 글 자동화 (프로그램으로 쓰기·수정) | 어려움 (에디터에 직접 붙여넣기) | 어려움 (Open API 2024년 종료) | 쉬움 (마크다운 파일을 저장소에 올리면 끝) |
| 디자인 자유도 | 낮음 (정해진 틀 안에서 꾸미기) | 중간 (스킨 편집 가능) | 높음 (전부 직접 구성) |
| 비용 | 무료 | 무료 | 도메인 값만 |
| 관리 부담 | 낮음 | 낮음 | 처음 설정에 손이 감 |
| 수익화 방식 | 애드포스트 (애드센스 불가) | 애드센스 가능 | 애드센스 (내 도메인으로 신청) |
| 검색 유입 | 네이버 검색에 강함 | 네이버 블로그보다 약함 | 네이버 유입은 약함 |

제 선택은 **네이버 블로그는 유지하면서 유입 창구로 쓰고, 본진은 직접 만든 블로그**로 두는 것이었습니다. 왜 그렇게 정했는지 하나씩 적어 볼게요.

## 네이버 블로그: 시작은 쉬웠지만 손이 많이 갔어요

### 글은 스마트에디터에 직접 붙여넣어야 합니다

2026년 10월 기준으로 네이버 블로그에는 외부 프로그램으로 글을 올리는 공식 글쓰기 기능이 없습니다. 그래서 미리 만든 원고가 있어도 결국 **스마트에디터를 열고 붙여넣는** 수밖에 없었습니다. 글을 고칠 때도 마찬가지예요. AI 도구로 원고를 다듬어도, 반영은 매번 손으로 해야 합니다.

### 어두운 스킨에서 글자가 안 보이는 문제

미리 만든 원고를 붙여넣었더니, 어두운 스킨에서 **일부 글자가 거의 보이지 않는** 문제가 생겼습니다. 원인은 붙여넣을 때 원본의 글자색과 배경색이 같이 딸려 들어온 것이었습니다.

> 어두운 배경 위에 어두운 글자색이 그대로 들어가면 글자가 배경에 묻힙니다. 붙여넣은 뒤에는 스킨에서 실제로 어떻게 보이는지 꼭 한 번 확인하세요.

### 카테고리·주제·꾸미기 설정

- 글이 <strong>'게임' 카테고리에 잘못 들어가</strong> 있어서 옮겼고, 블로그 주제도 **IT·컴퓨터**로 다시 설정했습니다.
- 타이틀, 프로필, 위젯, 모바일 커버까지 꾸미다 보니 생각보다 손이 많이 갔습니다.

### 그래도 확실한 강점: 네이버 검색 유입

네이버 블로그의 가장 큰 장점은 **네이버 자체 검색 유입**입니다. 네이버에서 검색했을 때 네이버 블로그 글이 잘 노출된다는 점은 다른 두 선택지에 비해 확실한 강점입니다.

다만 수익화는 **애드포스트**로 해야 하고, 애드센스는 붙일 수 없습니다. 애드센스를 원했던 제게는 이 부분이 아쉬웠습니다.

## 티스토리: 애드센스는 되지만 자동화가 막혔어요

티스토리는 **애드센스를 붙일 수 있고, 스킨도 편집할 수 있어서** 처음엔 가장 그럴듯한 선택지로 보였습니다.

문제는 두 번째 조건이었습니다. 예전에는 티스토리 Open API로 외부 프로그램에서 글을 올리고 고칠 수 있었는데, **이 Open API가 2024년에 종료**되었습니다. 그래서 프로그램으로 글쓰기·수정을 자동화하기가 어려워졌습니다. 이후 정책이 다시 바뀔 수도 있으니, 자동화를 생각한다면 티스토리 공식 공지를 먼저 확인해 보세요.

이 일을 보면서 느낀 점은, 남의 플랫폼 위에 있는 한 **정책이 바뀌면 그대로 영향을 받는다**는 것이었습니다. 지금 되는 기능이 내년에도 된다는 보장이 없어요.

## 직접 만든 블로그: 처음은 번거롭지만 원하는 걸 다 할 수 있었어요

### 서버를 직접 돌리는 안은 뺐습니다

마침 가비아에서 사 둔 도메인이 있었습니다. 처음에는 GCP 가상 서버를 빌려서 직접 운영하는 방법도 검토했는데, 다음 이유로 제외했습니다.

- 매달 나가는 **서버비**
- 운영체제와 프로그램의 **보안 업데이트**를 직접 챙겨야 함
- 서버가 멈추면 **장애 대응**도 직접 해야 함

### 대신 정적 사이트 + 무료 호스팅

그래서 고른 조합이 **Astro**(정적 사이트 생성기)와 **GitHub Pages**(무료 호스팅)입니다. 서버에서 프로그램이 돌아가는 구조가 아니라, 미리 만들어 둔 HTML 파일을 보여 주는 방식이라 관리할 서버가 없습니다.

글은 마크다운 파일 하나입니다. 이 글도 실제로 아래처럼 생긴 파일로 쓰고 있어요.

```markdown
---
title: "글 제목"
description: "검색 결과에 보이는 요약"
pubDate: 2026-10-03
category: "블로그 운영"
tags: ["태그1", "태그2"]
draft: true
---

## 본문은 여기부터

내용을 마크다운으로 씁니다.
```

이 파일을 저장소에 올리면 GitHub Actions가 사이트를 다시 만들어서 **30초 정도면 자동으로 배포**됩니다. 파일만 다루면 되니까 AI 도구로 초안을 쓰고 고치는 흐름과 잘 맞았습니다. `draft: true`로 두면 사이트에는 공개되지 않아서, 초안을 올려 두고 천천히 다듬을 수도 있습니다.

### 좋았던 점

- <strong>디자인이 완전히 자유롭습니다.</strong> 다크모드, 사이트 내 검색, RSS, 사이트맵을 원하는 대로 직접 구성했습니다.
- **비용은 도메인 값만** 듭니다. 호스팅은 무료입니다.
- 애드센스를 **내 도메인으로** 신청할 수 있습니다.

### 솔직한 단점

- <strong>처음 설정에 손이 많이 갑니다.</strong> 특히 도메인 연결에서 네임서버 문제로 꽤 고생했습니다. 이 과정은 [가비아 도메인 GitHub Pages 연결기](/blog/gabia-github-pages-domain/)에 따로 정리했습니다.
- <strong>네이버 검색 유입은 약합니다.</strong>
- <strong>댓글 기능이 기본으로 없습니다.</strong> 필요하면 따로 붙여야 합니다.
- 글을 **마크다운으로** 써야 합니다. 익숙하지 않으면 처음엔 어색할 수 있어요.

## 애드센스, 미리 알아 두면 좋은 점

애드센스는 사이트 게시자가 광고 수익의 일부를 받는 구조입니다. 구글 몫을 제외한 나머지를 받고, 직접 만든 블로그라면 <strong>중간에 플랫폼이 따로 나눠 갖지 않습니다.</strong>

다만 기대치는 낮게 잡는 게 좋습니다.

- <strong>승인 기준이 까다롭습니다.</strong> 직접 쓴 유용한 글이 충분히 있어야 하고, 소개·문의·개인정보처리방침 페이지도 갖춰야 합니다.
- 승인을 받아도 <strong>처음에는 수익이 매우 적습니다.</strong>

정확한 정책과 수익 배분은 바뀔 수 있으니 신청 전에 [애드센스 공식 고객센터](https://support.google.com/adsense/)를 꼭 확인하세요.

## 그래서 이렇게 나눠 쓰기로 했습니다

| 역할 | 플랫폼 | 이유 |
|---|---|---|
| 본진 (모든 글의 원본) | 직접 만든 블로그 | 글 자동화, 디자인 자유, 애드센스 |
| 유입 창구 | 네이버 블로그 | 네이버 검색 유입 |

네이버 블로그를 없애지 않은 이유는 단순합니다. 직접 만든 블로그의 가장 큰 약점이 네이버 유입인데, 그걸 네이버 블로그가 채워 줄 수 있기 때문입니다.

## 정리: 나에게 맞는 플랫폼 고르기 체크리스트

아래 질문에 답해 보면 방향을 잡기 쉽습니다.

- **네이버 검색 유입이 가장 중요하다** → 네이버 블로그
- **애드센스를 쓰고 싶지만 설정은 최소로 하고 싶다** → 티스토리
- **글을 파일로 관리하고, AI 도구나 프로그램으로 쓰고 고치고 싶다** → 직접 만든 블로그
- **디자인을 내 마음대로 바꾸고 싶다** → 직접 만든 블로그
- **처음 설정(도메인 연결, 배포 설정)에 시간을 쓸 수 있다** → 직접 만든 블로그도 가능
- **매달 서버비와 보안 관리는 피하고 싶다** → 서버형보다 정적 사이트 + 무료 호스팅

어느 하나가 정답이라기보다, **무엇을 가장 원하는지**에 따라 답이 달라집니다. 저는 자동화와 애드센스가 우선이었고, 대신 처음 설정의 번거로움과 네이버 유입의 약함을 감수했습니다. 그리고 그 약점은 네이버 블로그를 함께 쓰는 방식으로 보완하고 있습니다.

비슷한 고민을 하는 분께 조금이라도 참고가 되면 좋겠습니다.
